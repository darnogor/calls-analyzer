# Сервис `analyzer`

Оценивает транскрипт по промпту проекта и скриптам. Запись не слушает. Имена, сделку, заметку и произвольные поля звонка в модель не передаёт. В CRM не ходит.

Модель — внешний API, задаётся окружением (`LLM_MODEL`, ключ). Своя языковая модель в контейнере не запускается. В строке анализа остаётся фактическое имя модели. Конкретную модель выбирают по лучшему качеству оценки на потраченные деньги.

Итог считает сервис:

```text
overall = round(сумма по этапам: score * weight)
```

Веса берутся из карточки проекта в момент этой обработки и сохраняются в снимке. Позже правка настроек готовый итог не меняет.

## Вход

Очередь `calls.analyze`:

```json
{
  "message_id": "uuid",
  "project_id": "uuid",
  "call_id": "uuid",
  "attempt": 1,
  "enqueued_at": "2026-10-13T12:06:00+03:00"
}
```

Из базы собирается пакет для модели. В очередь он не кладётся.

```json
{
  "scorecard_version": 3,
  "ask_next_step": true,
  "scripts": [
    {
      "title": "Исходящий первый звонок",
      "body": "Представиться, назвать компанию, спросить, удобно ли говорить."
    }
  ],
  "transcript": [
    {
      "speaker": "manager",
      "start": 0.0,
      "end": 4.5,
      "text": "Добрый день, Алексей..."
    }
  ],
  "stages": [
    {
      "key": "opening",
      "title": "Открытие",
      "weight": 0.15,
      "instruction": "Начало разговора и установление контакта"
    },
    {
      "key": "needs",
      "title": "Потребность",
      "weight": 0.30,
      "instruction": "Выявление ситуации, проблемы и критериев выбора"
    },
    {
      "key": "presentation",
      "title": "Презентация",
      "weight": 0.20,
      "instruction": "Конкретность предложения под сказанное клиентом"
    },
    {
      "key": "objections",
      "title": "Возражения",
      "weight": 0.20,
      "instruction": "Работа с возражениями, включая стоимость"
    },
    {
      "key": "closing",
      "title": "Закрытие",
      "weight": 0.15,
      "instruction": "Зафиксирован ли следующий шаг"
    }
  ]
}
```

`scripts` — текущие скрипты проекта. Пустой список допустим: тогда оценка идёт только по промпту и транскрипту. Список `stages` равен промпту проекта, а не зашитым пяти ключам. Пример этапов выше — шаблон нового проекта.

Тот же список скриптов сервис пишет в `call_analysis.inputs_json`. Позже правка скрипта этот снимок не меняет. Поля записи в снимок не входят.

Если `overall_score` уже заполнен, модель не вызывается.

В начале работы статус `analyzing`. Одновременно не больше `ANALYZE_CONCURRENCY` заданий, старт — 2.

Полный текст системной инструкции в черновик не входит. Ответ модели — только JSON по ключам переданных этапов. Текст вне JSON считается ошибкой ответа.

```json
{
  "stages": {
    "opening": { "score": 85, "comment": "Хорошо установил контакт" },
    "needs": { "score": 70, "comment": "Выявил проблему, но не выяснил критерии выбора" },
    "presentation": { "score": 68, "comment": "Презентация слишком общая" },
    "objections": { "score": 55, "comment": "Слабо отработал возражение по стоимости" },
    "closing": { "score": 60, "comment": "Не зафиксирован следующий шаг" }
  },
  "summary": "Клиент заинтересован. Основная потребность выявлена.",
  "next_step_detected": false
}
```

Набор ключей в ответе совпадает с набором ключей запроса. `score` — целое 0–100. `comment` и `summary` не пустые. Поле итога в ответе модели игнорируется. `next_step_detected` обязателен, когда `ask_next_step=true`, и игнорируется, когда карточка этого не просит.

## Выход

Та же строка `call_analysis`:

| Поле | Откуда |
| --- | --- |
| `stages_json` | ключ, название и вес из запроса, оценка и комментарий из ответа |
| `summary` | `summary` |
| `next_step_detected` | ответ модели или пусто |
| `overall_score` | формула весов |
| `scorecard_version` | версия карточки, которая ушла в запрос |
| `ai_model` | фактическая модель |
| `created_at` | время успешной записи |

Пример шаблона и оценок 85, 70, 68, 55, 60:

```text
overall = round(85*0.15 + 70*0.30 + 68*0.20 + 55*0.20 + 60*0.15)
        = round(67.35)
        = 67
```

После записи `calls.processing_status=completed`. Следующей очереди нет.

## Ошибки

| Ситуация | Результат |
| --- | --- |
| нет транскрипта | повтор, затем `failed`, `error.stage=analyze`, `error.message=transcript_missing` |
| модель недоступна | повтор, затем `failed` |
| ответ не JSON, другой набор ключей или оценка вне 0–100 | повтор, затем `failed`, `error.message=invalid_model_json` |

Частичный набор оценок при ошибке не сохраняется.
