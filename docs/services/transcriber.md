# Сервис `transcriber`

Превращает файл записи в реплики с ролями и таймкодами. Оценку разговора не ставит и amoCRM не вызывает.

Провайдер распознавания — настройка контейнера (`STT_PROVIDER`, ключ, язык). На границе сервиса провайдера не видно: наружу выходит только JSON реплик. Язык по умолчанию в конфигурации — `ru`, пока вопрос 5 не закрыт.

Роли в первой версии назначаются так: две дорожки стерео — левая `manager`, правая `client`, если провайдер отдаёт каналы отдельно. Одна дорожка — провайдер диаризации помечает двух говорящих, первый говорящий в исходящем звонке считается менеджером, во входящем клиентом. Это рабочее правило до ответа о телефонии. Если говорящих больше двух, лишние реплики помечаются `client`. Роли `manager` и `client` — единственные допустимые в сохранённом JSON.

## Вход

Очередь `calls.transcribe`:

```json
{
  "message_id": "uuid",
  "call_id": "uuid",
  "attempt": 1,
  "enqueued_at": "2026-10-05T20:16:00+03:00",
  "audio": {
    "bucket": "recordings",
    "key": "calls/58374.mp3",
    "content_type": "audio/mpeg"
  }
}
```

Сервис читает объект из `minio` и строку `calls` (`direction` нужен для правила ролей). Если у этого `call_id` уже заполнен `call_analysis.transcript_json`, распознавание не повторяется и сразу публикуется выходное сообщение.

В начале работы ставит `processing_status=transcribing`. Создаёт строку `call_analysis`, если её ещё нет, и пока заполняет только связь `call_id`.

Параллельных заданий не больше `settings.transcribe_concurrency`.

## Выход

### Транскрипт

Пишется в `call_analysis.transcript_json`:

```json
[
  {
    "speaker": "manager",
    "start": 0.0,
    "end": 4.5,
    "text": "Добрый день, Алексей..."
  },
  {
    "speaker": "client",
    "start": 4.6,
    "end": 8.1,
    "text": "Да, здравствуйте..."
  }
]
```

Требования к массиву:

- порядок по возрастанию `start`;
- `end` больше `start`;
- `text` без пустых строк;
- `speaker` только `manager` или `client`;
- время в секундах от начала файла, дробное.

Оценки и `summary` этот сервис не заполняет.

### Сообщение `calls.analyze`

```json
{
  "message_id": "uuid",
  "call_id": "uuid",
  "attempt": 1,
  "enqueued_at": "2026-10-05T20:20:00+03:00"
}
```

Текста транскрипта в очереди нет. `analyzer` читает его из базы.

### Ошибки

| Ситуация | Результат |
| --- | --- |
| файл отсутствует в хранилище | повтор, затем `failed`, `error.stage=transcribe` |
| провайдер недоступен или ответил ошибкой | повтор, затем `failed` |
| провайдер вернул ноль реплик | повтор, затем `failed`, `error.message=empty_transcript` |
| реплики есть, но роли не удалось сопоставить | реплики всё равно пишутся по правилу выше; отдельным статусом это не считается |

Успешный выход не ставит `completed`. Этот статус принадлежит `analyzer`.
