# Сервис `transcriber`

Превращает файл в реплики с ролями и таймкодами. Оценку не ставит. Во внешние системы проекта, кроме провайдера распознавания, не ходит.

Провайдер — внешний API, задаётся окружением контейнера (`STT_PROVIDER`, ключ). Своя модель речи в контейнере не запускается. Язык распознавания — русский, `ru`, для всех проектов. Конкретный провайдер выбирается позже по лучшему качеству на потраченные деньги. Имя в этих документах не задано и сборку ядра не блокирует.

Роли остаются в репликах, чтобы дальше было видно, кто говорит. Две дорожки стерео — левая `manager`, правая `client`, если провайдер отдаёт каналы отдельно. Одна дорожка, в том числе смешанная запись, распознаётся целиком: провайдер помечает говорящих, первый говорящий в исходящем звонке считается менеджером, во входящем клиентом. При пустом `direction` первый говорящий считается менеджером. Если говорящих больше двух, остальные реплики помечаются `client`. В сохранённом JSON допустимы только `manager` и `client`.

Неуверенность в ролях не отменяет распознавание и не останавливает оценку. Отдельного статуса на этот случай нет. Экрана ручной правки ролей в первой версии нет.

## Вход

Очередь `calls.transcribe`:

```json
{
  "message_id": "uuid",
  "project_id": "uuid",
  "call_id": "uuid",
  "attempt": 1,
  "enqueued_at": "2026-10-13T12:02:00+03:00",
  "audio": {
    "bucket": "recordings",
    "key": "projects/p1/calls/58374.mp3",
    "content_type": "audio/mpeg"
  }
}
```

Сервис читает объект из `minio` и у звонка поле `direction`. Распознавание запрашивает на русском. Если `call_analysis.transcript_json` уже заполнен, распознавание не повторяется и сразу публикуется выход.

В начале работы статус `transcribing`. Строка `call_analysis` создаётся, если её ещё нет, и пока хранит только `call_id`.

Одновременно выполняется не больше `TRANSCRIBE_CONCURRENCY` заданий. Это потолок провайдера: сколько запросов распознавания он принимает сразу. Число задаётся окружением. Делёж слотов между проектами — в [архитектуре](../architecture.md).

## Выход

`call_analysis.transcript_json`:

```json
[
  {
    "speaker": "manager",
    "start": 0.0,
    "end": 4.5,
    "text": "Добрый день, Алексей..."
  },
  {
    "speaker": "client",
    "start": 4.6,
    "end": 8.1,
    "text": "Да, здравствуйте..."
  }
]
```

Требования: порядок по `start`, `end` больше `start`, `text` без пустых строк, роли только `manager` и `client`, время в секундах от начала файла.

Оценки и `summary` этот сервис не заполняет.

Сообщение `calls.analyze`:

```json
{
  "message_id": "uuid",
  "project_id": "uuid",
  "call_id": "uuid",
  "attempt": 1,
  "enqueued_at": "2026-10-13T12:06:00+03:00"
}
```

Текста в очереди нет. Его прочитает `analyzer` из базы.

## Ошибки

| Ситуация | Результат |
| --- | --- |
| файла нет в хранилище | повтор, затем `failed`, `error.stage=transcribe` |
| провайдер недоступен или вернул ошибку | повтор, затем `failed` |
| ноль реплик | повтор, затем `failed`, `error.message=empty_transcript` |

Реплики, размеченные по правилу выше, — нормальный выход, в том числе на одной дорожке. Дальше уходит весь транскрипт, со всеми говорящими. Статус `completed` ставит `analyzer`.
