# Допущения черновика 0.1

Эти решения нужны, чтобы описать входы и выходы сервисов до ответов на [открытые вопросы](open-questions.md). Если ответ изменит допущение, правим указанный документ, а не код: кода ещё нет.

| # | Допущение | Куда смотреть |
| --- | --- | --- |
| A1 | Одна установка обслуживает один аккаунт amoCRM. Поле `account_id` всё равно есть во всех ключевых таблицах: ТЗ уже требует уникальность `(account_id, external_call_id)`. | [data-model.md](data-model.md) |
| A2 | Вход пользователей в наш интерфейс пока не проектируем. API доступен внутри контура. Раздел «Настройки» описывает параметры обработки и OAuth amoCRM. | [product.md](product.md), [services/api.md](services/api.md) |
| A3 | Сервисы общаются асинхронно через Redis. Общая PostgreSQL — единственная база. У каждого сервиса свой набор таблиц, которые он пишет. | [architecture.md](architecture.md) |
| A4 | Язык реализации не выбран. Контракты описаны как HTTP и сообщения очереди, без привязки к BullMQ. Redis указан в ТЗ как транспорт очереди, его и фиксируем. | [architecture.md](architecture.md) |
| A5 | Запись звонка копируется в наше S3-совместимое хранилище сразу после обнаружения ссылки. Так конвейер не зависит от срока жизни `params.link`. | [services/media.md](services/media.md) |
| A6 | Речевой движок и LLM спрятаны за сервисами `transcriber` и `analyzer`. Провайдеры подставляются конфигурацией. В документах зафиксирован только JSON на границе. | [services/transcriber.md](services/transcriber.md), [services/analyzer.md](services/analyzer.md) |
| A7 | Итог `overall_score` считает `analyzer` по весам. Модель возвращает оценки этапов, комментарии и краткий вывод. | [services/analyzer.md](services/analyzer.md) |
| A8 | Веса по умолчанию: открытие 15%, потребность 30%, презентация 20%, возражения 20%, закрытие 15%. Их можно изменить в настройках. | [data-model.md](data-model.md) |
| A9 | Звонок короче порога не создаёт строку в `calls`. | [services/crm-sync.md](services/crm-sync.md) |
| A10 | Главная таблица показывает только звонки в статусе `completed`. Остальные статусы хранятся и доступны отдельным запросом, но в макет MVP не входят. | [services/api.md](services/api.md) |
| A11 | Фильтр «Все этапы» — текущая стадия сделки. Поиск — по имени контакта, названию компании и телефону. | [services/api.md](services/api.md) |
| A12 | Часовой пояс интерфейса и граница «сегодня» — `Europe/Moscow`. | [services/web.md](services/web.md) |
| A13 | Первичный импорт — 30 дней. Повторный полный импорт вручную в MVP не описываем. | [services/crm-sync.md](services/crm-sync.md) |
| A14 | Синхронизация пользователей — при подключении, далее каждые 6 часов и по кнопке «Обновить данные». | [services/crm-sync.md](services/crm-sync.md) |
| A15 | Резервный опрос amoCRM — каждые 90 секунд, окно назад 15 минут. | [services/crm-sync.md](services/crm-sync.md) |
| A16 | Если ссылки на запись ещё нет, `crm-sync` перечитывает примечание через 1, 5 и 15 минут. После этого статус `recording_missing`. | [services/crm-sync.md](services/crm-sync.md) |
| A17 | Ручное сопоставление номера телефонии и менеджера описано как запасной вход, таблица есть в модели. Экрана для него в MVP нет, пока вопрос 9 не отвечен. | [data-model.md](data-model.md) |
| A18 | Адаптер конкретной телефонии живёт внутри `media` как второй способ получить файл. Отдельный контейнер появится, только если протокол телефонии этого потребует. | [services/media.md](services/media.md) |
| A19 | Публикуется наружу только `ingress`. Остальные контейнеры в внутренней сети Docker. | [architecture.md](architecture.md) |
