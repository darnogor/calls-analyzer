# Принятые решения

На этих решениях держатся контракты. Кода ещё нет. Единственный открытый пункт — чеклист одного живого звонка amoCRM в [вопросах](open-questions.md). Он не блокирует ядро. Имена провайдеров речи и оценки выбираются позже и ядро тоже не блокируют.

| # | Решение | Куда смотреть |
| --- | --- | --- |
| A1 | Установка содержит много проектов. Данные проекта изолированы `project_id`. Проект может обойтись без CRM. | [product.md](product.md) |
| A2 | Администратор может всё в установке. Руководитель ведёт данные своего проекта. Менеджер по продажам только читает. Вход — почта и пароль, самостоятельной регистрации нет. | [product.md](product.md), [services/api.md](services/api.md) |
| A3 | Сервисы ядра передают работу через Redis. База ядра одна. Плагин пишет только по HTTP и в свою базу. | [architecture.md](architecture.md) |
| A4 | Ядро и плагин пишутся на TypeScript. Сервисы ядра с HTTP и очередями — NestJS в npm workspaces. `web` остаётся статическим интерфейсом. Контракты — HTTP и сообщения очереди. Redis остаётся транспортом очереди. Общий клиент chat-completions вызывает только `analyzer`. | [architecture.md](architecture.md) |
| A5 | Файл по URL ядро копирует в хранилище. Файл с формы пишет `api`. Если URL требует секрет CRM или телефонии, источник скачивает файл сам и присылает байты. | [intake.md](intake.md), [services/media.md](services/media.md) |
| A6 | Распознавание и оценка вызывают внешние API. Локальные модели не запускаются. Провайдера и модель выбирают позже по лучшему качеству на потраченные деньги и задают окружением. Сервис сам другую модель не подставляет. Имена провайдеров документы не фиксируют. На границе сервисов виден JSON. | [services/transcriber.md](services/transcriber.md), [services/analyzer.md](services/analyzer.md) |
| A7 | На оценку влияют весь транскрипт, включая реплики всех говорящих, промпт и все скрипты проекта. Выбора скрипта на звонок нет. Итог считает `analyzer` по весам. Поля записи в модель не уходят. Отдельный признак следующего шага модель не возвращает. | [services/analyzer.md](services/analyzer.md) |
| A8 | Пять этапов продажи фиксированы: `opening`, `needs`, `presentation`, `objections`, `closing`. Меняются названия, веса и формулировки. Готовые звонки не пересчитываются. | [product.md](product.md) |
| A9 | Известная длительность ниже порога отклоняется ответом `422`, строки нет. До платного распознавания длительность обязана быть известна. Из файла и ниже порога — `skipped_short`. Прочитать нельзя — `skipped_no_duration`, это не сбой провайдера. Сообщения `calls.transcribe` в обоих случаях нет. Плагин до отправки читает только этот порог своим `source_token`. | [services/media.md](services/media.md), [services/api.md](services/api.md) |
| A10 | Главная таблица показывает только `completed`. Список проблем (`failed`, `recording_missing`, `skipped_short`, `skipped_no_duration`) и список звонков в работе (`recording_pending`, `audio_queued`, `audio_fetch`, `transcribing`, `analyzing`) видят администратор и руководитель. Менеджер по продажам эти списки не видит. Карточка по id показывает текущий статус; при `failed` в ней есть `error`. | [services/api.md](services/api.md), [product.md](product.md) |
| A11 | Фильтр звонков по стадии — текущая стадия сделки, параметр `deal_status`. Пустой пункт подписан «Все стадии». «Этапы» остаются только этапами карточки оценки. Поиск — контакт, компания, телефон, имя менеджера и название сделки. | [services/api.md](services/api.md), [product.md](product.md) |
| A12 | Часовой пояс нового проекта — `Europe/Moscow`. Его можно сменить в настройках проекта. | [data-model.md](data-model.md) |
| A13 | К проекту можно подключить несколько плагинов. Ручной источник есть всегда. | [product.md](product.md) |
| A14 | Колонки таблицы следуют текущей карточке. Карточка звонка показывает снимок этапов того анализа: у этапа есть формулировка и вес, которые ушли в модель. Поздняя правка промпта снимок не меняет. | [product.md](product.md), [services/api.md](services/api.md) |
| A15 | Язык записей, транскриптов и промптов — русский на всю установку. Отдельного выбора языка у проекта нет. | [services/transcriber.md](services/transcriber.md) |
| A16 | Распознавание и оценка — внешние API со своими потолками. Потолок равен тому, сколько запросов этого типа провайдер принимает сразу, и задаётся окружением. Один проект не занимает потолок целиком: при потолке от 2 один слот остаётся другому проекту, даже если тот не ждёт; при потолке 1 слот можно занять. Проект берёт остальные слоты. Свободный слот отдаётся тому, кто ждёт дольше. | [architecture.md](architecture.md) |
| A17 | Снаружи опубликован только `ingress`. Вся установка — один сервер и один `docker-compose`: ядро, плагин, база, очередь и хранилище. Отдельного облачного S3 нет. У каждого прикладного сервиса есть проверка живости. | [architecture.md](architecture.md) |
| A18 | Первый и пока единственный описанный плагин — amoCRM. Опрос, импорт истории, словарь добавочных и ожидание ссылки, которой ещё нет, принадлежат ему. Повторы amoCRM — 60, 300 и 900 секунд. Ядро `recording_pending` не опрашивает и про CRM не знает. Поздний файл принимается, пока статус `recording_pending`. | [plugins/amocrm.md](plugins/amocrm.md), [intake.md](intake.md) |
| A19 | Весь звонок распознаётся, в том числе одна смешанная дорожка. Если есть каналы, роли берутся из них. На одной дорожке первый говорящий в исходящем — менеджер, во входящем — клиент. Неуверенность в ролях конвейер не останавливает. Экрана правки ролей в первой версии нет. | [services/transcriber.md](services/transcriber.md), [services/analyzer.md](services/analyzer.md) |
