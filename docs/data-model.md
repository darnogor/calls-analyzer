# Модель данных ядра

База PostgreSQL ядра. Имена ниже — логические. Физические типы и миграции появятся вместе с кодом.

Идентификаторы строк ядра — UUID. Идентификатор во внешней системе хранится строкой в `external_id` и имеет смысл только вместе с `source_id`. Полей amoCRM в этой схеме нет. Токены и сырые события CRM лежат в базе плагина, см. [plugins/amocrm.md](plugins/amocrm.md).

## `accounts`

Человек, который входит в установку. Это не менеджер звонка.

| Поле | Смысл |
| --- | --- |
| `id` | id аккаунта |
| `email` | почта, уникальная в установке |
| `name` | имя на экранах входа и списка аккаунтов |
| `password_hash` | хэш пароля; сам пароль не хранится |
| `is_administrator` | администратор установки |
| `is_active` | выключенный аккаунт не входит |
| `created_at`, `updated_at` | метки |

Первая строка с `is_administrator=true` создаётся при выкладке. Последнюю такую активную строку сервис не выключает.

## `project_memberships`

Доступ аккаунта к проекту. Администратор видит все проекты и без этой строки.

| Поле | Смысл |
| --- | --- |
| `id` | id |
| `account_id` | аккаунт |
| `project_id` | проект |
| `role` | `lead` (руководитель) или `sales_manager` (менеджер по продажам) |
| `created_at` | когда выдали доступ |

Уникальность: `(account_id, project_id)`.

## `projects`

| Поле | Смысл |
| --- | --- |
| `id` | id проекта |
| `name` | название в списке проектов |
| `timezone` | пояс для границы «сегодня», по умолчанию `Europe/Moscow` |
| `min_call_duration_sec` | порог анализа, по умолчанию 180 |
| `created_at` | создание |

## `scorecards`

Одна текущая карточка на проект. Каждое сохранение увеличивает `version`.

| Поле | Смысл |
| --- | --- |
| `project_id` | проект |
| `version` | целое, с 1 |
| `stages_json` | упорядоченный список этапов |

Элемент `stages_json`:

```json
{
  "key": "opening",
  "title": "Открытие",
  "weight": 0.15,
  "instruction": "Начало разговора и установление контакта"
}
```

`key` уникален внутри карточки и не меняется при правке названия. Сумма `weight` равна 1. Шаблон нового проекта — пять этапов из [продукта](product.md). Карточку пишет администратор.

## `project_inputs`

Скрипты проекта. В оценку уходят все скрипты проекта, выбора скрипта на звонок нет. Модель читает их вместе с транскриптом и промптом. Промпт живёт в `scorecards`.

| Поле | Смысл |
| --- | --- |
| `id` | id |
| `project_id` | проект |
| `title` | название |
| `body` | как должен проходить разговор |
| `updated_at` | последняя правка |

Произвольные данные конкретной записи в эту таблицу не кладутся. Они лежат на звонке и в оценку не входят.

## `sources`

Откуда в проект приходят звонки. У каждого проекта с момента создания есть один источник `kind=manual`.

| Поле | Смысл |
| --- | --- |
| `id` | id источника |
| `project_id` | проект |
| `kind` | `manual` или `plugin` |
| `provider` | для ручного пусто; для первого плагина `amocrm` |
| `display_name` | подпись в настройках |
| `token_hash` | хэш `source_token`; сам токен хранится только у плагина |
| `last_intake_at` | последний успешный приём звонка или справочника |
| `created_at` | создание |

## `managers`

| Поле | Смысл |
| --- | --- |
| `id` | id в ядре |
| `project_id` | проект |
| `source_id` | источник, создавший строку |
| `external_id` | id у источника; у ручного менеджера пусто |
| `name` | имя для экрана |
| `email` | почта, если передана |
| `is_active` | показывать в фильтрах и в списке менеджеров |
| `created_at`, `updated_at` | метки |

Уникальность плагинного менеджера: `(project_id, source_id, external_id)`.

Имя плагинного менеджера меняет только повторный приём от того же источника. Имя ручного менеджера меняют администратор и руководитель.

## `contacts`

| Поле | Смысл |
| --- | --- |
| `id` | id в ядре |
| `project_id` | проект |
| `source_id` | источник |
| `external_id` | id у источника; у ручного контакта пусто |
| `name` | имя |
| `company_name` | текущее название компании |
| `external_url` | готовая ссылка или пусто |
| `updated_at` | последнее обновление |

Уникальность плагинного контакта: `(project_id, source_id, external_id)`.

Ядро не собирает URL из поддомена и числового id.

## `calls`

| Поле | Смысл |
| --- | --- |
| `id` | id в ядре |
| `project_id` | проект |
| `source_id` | источник |
| `external_id` | id звонка у источника; у ручной загрузки без ключа ядро кладёт свой uuid |
| `idempotency_key` | ключ повтора формы, если его прислали |
| `manager_id` | менеджер, может быть пустым |
| `contact_id` | контакт, может быть пустым |
| `company_name` | компания на момент звонка; поздняя правка контакта её не меняет |
| `direction` | `in`, `out` или пусто |
| `phone` | номер |
| `started_at` | начало |
| `duration_sec` | секунды; если при приёме было пусто, `media` читает их из метаданных, а если там пусто — из файла. Прочитать нельзя — поле остаётся пустым |
| `recording_source_url` | URL, который просили скачать |
| `recording_storage_key` | ключ объекта |
| `recording_content_type` | MIME |
| `deal_external_id` | id сделки у источника |
| `deal_name` | название на момент звонка; поздняя правка в CRM его не меняет |
| `deal_status_at_call_name` | стадия в момент звонка |
| `current_deal_status_name` | текущая стадия |
| `deal_external_url` | готовая ссылка |
| `deal_link_status` | `linked`, `unresolved`, `ambiguous`, `absent` |
| `context_json` | заметка и произвольные поля для экрана и фильтра; в оценку не входят |
| `processing_status` | см. [architecture.md](architecture.md) |
| `error` | JSON сбоя |
| `created_at`, `updated_at` | метки |

Уникальность: `(project_id, source_id, external_id)`.

Отдельной таблицы сделок нет. Обновление текущей стадии ищет звонки по `(project_id, source_id, deal_external_id)`.

## `call_analysis`

Одна строка на звонок. Этапы хранятся снимком, а не колонками `opening_score`. В снимке остаются название, вес и формулировка на момент оценки. Ключи в первой версии фиксированы.

| Поле | Смысл |
| --- | --- |
| `id` | id |
| `call_id` | звонок, уникальный |
| `transcript_json` | массив реплик |
| `inputs_json` | снимок всех скриптов проекта, ушедших в модель; поздняя правка скрипта его не меняет |
| `stages_json` | оценки, комментарии, веса, названия и формулировки на момент оценки |
| `overall_score` | итог по весам снимка, целое 0–100 |
| `summary` | краткий вывод |
| `ai_model` | имя модели, которая фактически ответила |
| `created_at` | время записи оценки |

Элемент транскрипта:

```json
{
  "speaker": "manager",
  "start": 0.0,
  "end": 4.5,
  "text": "Добрый день, Алексей..."
}
```

`speaker` — `manager` или `client`. В массиве лежит весь разговор, не только реплики менеджера. Время — секунды от начала файла. Как ставится роль — в [transcriber.md](services/transcriber.md).

Элемент `stages_json`:

```json
{
  "key": "opening",
  "title": "Открытие",
  "weight": 0.15,
  "instruction": "Начало разговора и установление контакта",
  "score": 85,
  "comment": "Хорошо установил контакт"
}
```

## Чего в ядре нет

Таблиц подключений CRM, токенов, воронок, сырых webhook и словаря добавочных. Агрегаты менеджера не хранятся отдельно: `api` считает их по `call_analysis` за период. Компания не выделена в свою сущность: это строка на контакте и на звонке.
