# Плагины CRM

Плагин — отдельный контейнер. Он знает одну внешнюю систему и не знает, как устроены транскрипт и оценка. В ядро он входит только через [контракт приёма](../intake.md).

Ядро работает без единого плагина. Первый описанный плагин — [amoCRM](amocrm.md). Следующая CRM повторяет этот контракт и получает свой контейнер. Общего контейнера «все CRM» нет: правила сущностей у систем разные, а формат на выходе один.

## Что плагин забирает себе

- учётные данные своей системы и их обновление;
- приём событий и резервный опрос;
- сопоставление менеджера, контакта, компании и сделки;
- человеческие названия стадий и готовую ссылку на карточку;
- решение, когда записи ещё нет и когда её уже не будет;
- скачивание файла, если URL нельзя отдать ядру без секрета;
- исторический импорт и кнопку обновления справочников.

## Что плагин отдаёт ядру

На каждый подходящий звонок — `POST /api/projects/{project_id}/calls` с телом из контракта приёма.

Дальше по необходимости:

- приложить URL или файл к уже созданному звонку;
- сообщить, что записи не будет;
- обновить справочник менеджеров;
- обновить имя контакта и текущую стадию сделки.

Плагин не пишет в PostgreSQL ядра, не ставит сообщения в `calls.*` и не вызывает `media`, `transcriber` и `analyzer`.

## Как появляется связка

1. Администратор или руководитель в разделе входных данных проекта создаёт источник и получает одноразовый `setup_code`.
2. Открывает страницу плагина. Код уходит в плагин вместе с запуском авторизации внешней системы.
3. После успешной авторизации плагин обменивает код на `source_token`.
4. Токен хранится в базе плагина. В ядре остаётся только его хэш.
5. Плагин передаёт звонки в проект, чей id был внутри кода.

Пока код не обменян, плагин не знает, в какой проект писать. Ядро на этом шаге не получает токен CRM.

Обмен описан в [api](../services/api.md). Страница авторизации описана в документе конкретного плагина.

## Общие правила выхода

- Длительность ниже порога плагин может не присылать. Если пришлёт, ядро ответит `422` и строку не создаст. Порог плагин может прочитать у ядра вместе с настройками проекта, чтобы не слать заведомо короткие разговоры.
- `external_id` стабилен для одного разговора. Повтор webhook не порождает вторую оценку.
- `external_url` плагин собирает сам.
- `link_status=ambiguous` плагин ставит сам, когда по своим правилам сделку выбрать нельзя. Ядро сделку не угадывает.
- Стадия на момент звонка и текущая стадия приходят уже текстом.
- Файл по защищённому адресу плагин скачивает своими секретами и передаёт байтами.
