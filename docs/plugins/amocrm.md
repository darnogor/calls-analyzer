# Плагин `plugin-amocrm`

Необязательный контейнер. Забирает менеджеров, звонки, контакты и сделки из amoCRM и передаёт их в проект ядра по [контракту приёма](../intake.md). Транскрипцию не строит, файл в хранилище ядра сам не кладёт, оценку не считает.

amoCRM в этом документе — конкретная система. Другая CRM повторяет границу, описанную в [plugins/README.md](README.md), и не обязана повторять правила ниже.

У плагина своя база `plugin_amocrm`. К базе ядра он не подключается. Очереди плагина в Redis начинаются с `plugin.amocrm.` и воркерами ядра не читаются.

## Вход

### Связка с проектом

Человек открывает:

```http
GET /plugins/amocrm/connect?setup_code={code}
```

`setup_code` выпущен ядром в настройках проекта. Плагин перенаправляет браузер на страницу разрешения amoCRM. В `state` лежит этот код.

```http
GET /plugins/amocrm/oauth/callback?code={amo_code}&state={setup_code}
```

Плагин меняет код amoCRM на токены, обменивает `setup_code` на `source_token` ядра и пишет строку `connections`. Сразу после этого ставит себе команды `sync_reference` и `import_history`.

Секрет клиента OAuth amoCRM и redirect URI — переменные окружения контейнера. `source_token` в переменные окружения не зашивается: он свой у каждой связки.

### Webhook

```http
POST /plugins/amocrm/webhooks/{connection_id}
```

Тело — webhook amoCRM о примечании. Плагин пишет его в `amo_events` со `source=webhook` и `process_status=pending`, ставит сообщение в `plugin.amocrm.events` и отвечает `200`. Разбор в этом HTTP-запросе не выполняется.

Если путь не совпал с известным `connection_id`, ответ `401`, событие не пишется.

```json
{
  "message_id": "uuid",
  "connection_id": "uuid",
  "amo_event_id": "uuid",
  "attempt": 1,
  "enqueued_at": "2026-10-13T12:00:00+03:00"
}
```

### Резервный опрос

Таймер раз в `poll_interval_sec` запрашивает у amoCRM примечания `call_in` и `call_out` за окно `poll_lookback_sec`. Новое примечание становится событием со `source=poll` и таким же сообщением очереди.

### Команды

Очередь `plugin.amocrm.commands`:

```json
{
  "message_id": "uuid",
  "connection_id": "uuid",
  "command": "sync_reference",
  "enqueued_at": "2026-10-13T12:00:00+03:00"
}
```

| `command` | Кто ставит | Действие |
| --- | --- | --- |
| `sync_reference` | страница плагина или сам плагин после OAuth | пользователи, воронки, текущие стадии сделок, уже переданных в ядро |
| `import_history` | сам плагин один раз после OAuth | звонки за `import_days` |

Повторный `import_history` при заполненном `history_imported_at` новых звонков не создаёт.

Кнопка «Обновить данные» стоит на странице этого плагина. Ядро такой кнопки не публикует.

### Ответы amoCRM

Плагин читает:

- пользователя: `id`, `name`, `email`, группу, признак активности;
- примечание: `id`, `note_type` (`call_in` или `call_out`), `entity_id`, тип родителя (`contacts`, `leads`, `companies`), `created_by`, `responsible_user_id`, `params.uniq`, `params.duration`, `params.link`, `params.phone`, `params.source`, `params.call_responsible`;
- контакт со сделками и компанией;
- сделку с контактами;
- компанию с контактами;
- воронки и статусы, включая признак успешного и проигранного статуса.

Имена полей сверяются на одном реальном звонке. Если поля нет, соответствующее значение в теле для ядра остаётся пустым, и плагин идёт по правилам ниже.

### Настройки связки

Перед отправкой в ядро плагин читает порог проекта. Свои интервалы он хранит в `connections`:

| Поле | Стартовое значение |
| --- | --- |
| `import_days` | 30 |
| `user_sync_interval_hours` | 6 |
| `poll_interval_sec` | 90 |
| `poll_lookback_sec` | 900 |
| `recording_recheck_delays_sec` | 60, 300, 900 |

Порог длительности принадлежит проекту ядра. Интервалы опроса принадлежат связке.

## Выход в ядро

Все вызовы идут с `Authorization: Bearer {source_token}` на проект из `connections.project_id`.

### Менеджеры

`sync_reference` отправляет `PUT /api/projects/{project_id}/managers` текущим списком пользователей amoCRM. Поле `is_active` повторяет признак активности в amoCRM. Пользователя, которого этот API больше не возвращает, в списке нет: ядро снимает активность с менеджера источника, отсутствующего в теле.

`external_id` менеджера — строковый id пользователя amoCRM. Группа amoCRM в ядро не передаётся.

Тот же проход обновляет локальные `pipelines` и `pipeline_statuses`. В ядро справочник воронок не отправляется: ядру нужны только тексты стадий на конкретных звонках.

Для сделок, которые плагин уже отправлял, он вызывает `PATCH .../deals/by-external-id/{id}` с новым `current_status_name` и актуальным `external_url`. Название сделки и стадию на момент звонка этот вызов не трогает: контракт ядра их не меняет. `deal_name` на старых звонках остаётся тем, что было передано при создании.

Плагин собирает ссылки сам:

```text
https://{subdomain}.amocrm.ru/contacts/detail/{contact_id}
https://{subdomain}.amocrm.ru/leads/detail/{lead_id}
```

Смена поддомена попадает в ядро следующим `PATCH` контакта или сделки.

`connections.last_user_sync_at` и `last_poll_at` плагин пишет у себя. Успешный конец импорта истории пишет `history_imported_at`.

### Один звонок

На сообщение из `plugin.amocrm.events` плагин дочитывает примечание через API amoCRM.

1. Тип не `call_in` и не `call_out` — событие `ignored`, в ядро ничего не уходит.
2. `duration` меньше порога проекта — событие `ignored`, в ядро ничего не уходит.
3. Этот `external_id` уже отправлялся. Если запись тогда была не готова, а сейчас в примечании есть ссылка, плагин прикладывает запись. Новую карточку не создаёт.
4. Плагин определяет контакт, компанию, сделку и менеджера.
5. Плагин вызывает `POST /api/projects/{project_id}/calls`.

`external_id` равен `params.uniq`. Если `uniq` пустой, равен строковому id примечания.

`direction`: `call_in` → `in`, `call_out` → `out`.

`started_at` берётся из времени звонка в примечании. Если телефония его не присылает, плагин ставит время создания примечания.

Пример тела, которое уходит в ядро, когда ссылка уже есть и её можно скачать без сессии amoCRM:

```json
{
  "external_id": "8f2c1a",
  "direction": "out",
  "phone": "+79990000000",
  "started_at": "2026-04-28T16:42:00+03:00",
  "duration_sec": 1458,
  "recording": {
    "type": "url",
    "url": "https://records.example/abc.mp3"
  },
  "manager": {
    "external_id": "123",
    "name": "Анна Петрова",
    "email": "anna@example.com"
  },
  "contact": {
    "external_id": "456",
    "name": "Алексей Смирнов",
    "external_url": "https://example.amocrm.ru/contacts/detail/456"
  },
  "company_name": "ООО Альфа",
  "deal": {
    "external_id": "789",
    "name": "Поставка",
    "status_at_call_name": "Переговоры",
    "current_status_name": "Переговоры",
    "external_url": "https://example.amocrm.ru/leads/detail/789",
    "link_status": "linked"
  },
  "context": {
    "notes": "",
    "fields": []
  }
}
```

Если ссылки нет, блок `recording` не передаётся. Ядро отвечает `recording_pending`. Плагин запоминает пару `external_id` и id примечания у себя.

Если ссылка есть, но без секрета телефонии не скачивается, плагин забирает байты сам и шлёт тот же `POST` как `multipart`: JSON в части `payload` без `recording`, аудио в части `file`.

### Менеджер звонка

Первое сработавшее правило:

1. `responsible_user_id`, если этот пользователь есть в локальном справочнике.
2. `params.call_responsible`, если это числовой id пользователя amoCRM из справочника.
3. `created_by`, если он есть в справочнике.
4. Совпадение телефона или добавочного из `params.source` со строкой `telephony_extensions`.

Найденный пользователь попадает в блок `manager` с `external_id`. Если не сработало ни одно правило, блок `manager` не отправляется, звонок в ядро всё равно уходит.

### Контакт и компания

| Родитель примечания | Что делает плагин |
| --- | --- |
| контакт | читает контакт со сделками; в тело кладёт `external_id`, имя и компанию |
| сделка | читает сделку с контактами и берёт главный контакт |
| компания | читает компанию и связанные контакты |

Главный контакт — тот, кого amoCRM помечает главным. Если метки нет и контакт один, берётся он. Если контактов несколько и главного нет, блок `contact` пустой. Название компании при этом всё равно уходит в `company_name`, когда компания известна.

### Сделка

1. Примечание прикреплено к сделке — `link_status=linked` и эта сделка.
2. У контакта ровно одна активная сделка — `link_status=linked` и она.
3. Активных сделок несколько — блока с id нет, `link_status=ambiguous`.
4. Иначе `link_status=unresolved`.

Активная сделка — статус не успешный и не проигранный по локальному справочнику воронок. Случайную сделку из нескольких плагин не выбирает.

При `linked` в тело попадают id, название, обе стадии одним и тем же текстом и готовый URL. Бюджет сделки в ядро не передаётся.

### Повторное чтение записи

Для отправленного звонка без файла плагин снова запрашивает примечание через 60, 300 и 900 секунд. Это ожидание ссылки, которой ещё нет: его ведёт плагин. Ядро в это время `recording_pending` не опрашивает и про CRM не знает. Поздний файл ядро принимает, пока статус звонка остаётся `recording_pending`.

Появился доступный URL — `POST .../calls/by-external-id/{external_id}/recording` с `{ "type": "url", "url": "..." }`. Файл доступен только с секретом — тот же путь через `multipart`. Три интервала прошли без записи — `POST .../recording/missing`.

### Импорт истории

`import_history` берёт `call_in` и `call_out` за `import_days` и проводит каждый через те же правила. В ядро уходят только звонки не короче порога. Скорость распознавания ограничивает ядро, не этот контейнер.

## База плагина

### `connections`

| Поле | Смысл |
| --- | --- |
| `id` | id связки |
| `project_id` | проект ядра |
| `source_id` | источник в ядре |
| `source_token` | токен приёма |
| `amo_account_id` | аккаунт amoCRM |
| `amo_subdomain` | поддомен для ссылок |
| `access_token`, `refresh_token`, `token_expires_at` | токены amoCRM |
| `last_user_sync_at`, `last_poll_at`, `history_imported_at` | служебные метки |
| интервалы из таблицы настроек | на эту связку |

### `amo_events`

Журнал webhook и опроса: `id`, `connection_id`, `source` (`webhook` или `poll`), `payload`, `received_at`, `processed_at`, `process_status` (`pending`, `processed`, `ignored`, `failed`), `external_id` отправленного звонка.

### `pipelines` и `pipeline_statuses`

Локальный справочник, чтобы отличить активную сделку от успешной и проигранной. В ядро не копируется.

### `telephony_extensions`

`connection_id`, `extension`, `amo_user_id`. Уникальность `(connection_id, extension)`. Экрана правки в первой версии нет. Он появится, только если живой звонок покажет, что менеджера иначе не найти. До этой проверки код плагина не пишем: сначала один реальный звонок из подключённой телефонии.

### `pending_recordings`

`connection_id`, `external_id`, `amo_note_id`, `attempts_done`, `next_check_at`. Нужна, чтобы повторы чтения ссылки не зависели от статусов ядра.

## Ошибки

Ошибка API amoCRM на одном событии: три попытки сообщения, затем `amo_events.process_status=failed`. Если карточка в ядро уже ушла, а запись приложить не удалось, это видно по статусу звонка в ядре после вызова прикладывания. До успешного `POST` строки звонка в ядре нет.

Истёкший access token amoCRM обновляется один раз, запрос повторяется. Повторный отказ останавливает разбор и таймеры этой связки до нового OAuth. Страница плагина показывает, что авторизация amoCRM требует повтора. Ядро при этом продолжает принимать ручные звонки проекта.
